Git & GitHub Placement Quick Revision Notes

Essential Architecture, CLI Cheatsheet, Merge Conflicts & 10 Golden Placement Rules

1. The Three-Tree Architecture & Lifecycle

Git manages files across three distinct states on your local machine before syncing to GitHub:

1. Working Tree Local Sandbox

Actual files on disk you edit in VS Code. Unmodified, modified, or untracked.

git status
➜
2. Staging / Index Commit Drafter

Snapshot preparation zone. Exact files and line-diffs ready for commit.

git add <file>
➜
3. HEAD / Repository Permanent History

Cryptographic DAG commits stored permanently in .git/objects.

git commit -m "..."

2. High-Frequency CLI Command Master Cheatsheet

Command Primary Purpose MNC Placement Trap to Avoid
git init Initializes an empty local repository (creates hidden .git). Do not use on cloned repos; git clone already initializes .git.
git status -s Displays short status: M (modified), A (added), ?? (untracked). Does not show file line diffs, only file tracking states.
git diff vs git diff --staged git diff: Working Tree vs Staging.
--staged: Staging vs Last Commit.		 Running git diff after git add returns blank because changes are already staged!
git commit --amend Modifies the most recent commit message or adds staged files to it. Only use on local commits! Never amend commits already pushed to shared branches.
git switch -c <branch> Modern Git 2.23+ command to create and switch to a branch. Cleaner than legacy git checkout -b which conflated file restore with branch switching.
git fetch vs git pull fetch downloads remote commits without merging.
pull = fetch + merge.		 pull can trigger unexpected merge conflicts; run fetch and inspect first.
git stash pop Applies temporarily stashed uncommitted edits and deletes from stash list. git stash apply applies edits but keeps them in the stash stack.

3. Fast-Forward vs 3-Way Merge vs Rebase

Fast-Forward Merge

Occurs when the target branch has no diverging commits since the feature branch split. Git simply moves the target pointer forward without creating a new merge commit.

Zero Merge Commit

3-Way Recursive Merge

Occurs when both branches have new commits. Git uses the common ancestor + tips of both branches to generate a dedicated merge commit with 2 parents.

Creates Merge Commit

Git Rebase

Re-plays feature commits on top of the latest target branch tip, creating a completely linear history. Rewrites commit SHA hashes!

Never Rebase Shared Branches

4. Resolving Merge Conflicts in 5 Steps

  1. Identify Conflicted Files: Run git status to locate files labeled both modified.
  2. Open Conflicted Files: Look for Git conflict markers: 
    <<<<<<< HEAD (Current branch code)
Enterprise production code
=======
Feature branch new code
>>>>>>> feature-xyz (Incoming branch code)
  3. Edit & Clean: Delete the markers (<<<, ===, >>>) and keep the intended combined code.
  4. Mark Resolved: Run git add <resolved-file> to stage the conflict resolution.
  5. Complete Merge: Run git commit (or git rebase --continue if rebasing). To cancel, run git merge --abort.

5. Reset vs Revert vs Restore (Placement Holy Grail)

Command Working Tree Staging / Index HEAD Pointer Safe for Public/Shared Branch?
git reset --soft HEAD~1 Kept untouched Changes staged Moved back 1 commit ❌ Local only (rewrites history)
git reset --mixed HEAD~1 (Default) Kept untouched Unstaged Moved back 1 commit ❌ Local only (rewrites history)
git reset --hard HEAD~1 Destroyed Destroyed Moved back 1 commit ❌ Dangerous (recovers only via git reflog)
git revert <commit-hash> Updated safely Updated safely Creates NEW inverse commit ✅ 100% Safe for shared remote branches

6. 10 Golden Placement Rules (MNC Screenings)

  • Rule 1: Git is completely offline. GitHub is remote. You can branch, commit, and diff without internet.
  • Rule 2: Deleting the root .git folder deletes your entire repository database and all history.
  • Rule 3: git pull = git fetch + git merge.
  • Rule 4: Never run git reset --hard on shared branches; use git revert to preserve team history.
  • Rule 5: Files already committed before adding to .gitignore must be untracked using git rm --cached <file>.
  • Rule 6: Accidental hard resets can be recovered using git reflog before garbage collection.
  • Rule 7: Local config (.git/config) always overrides Global config (~/.gitconfig).
  • Rule 8: Shallow clones (git clone --depth 1) fetch only the newest snapshot without 10-year history to save bandwidth.
  • Rule 9: A detached HEAD means HEAD points directly to a commit SHA rather than a named branch reference.
  • Rule 10: git merge --abort safely resets your workspace to the exact state before the conflicted merge started.
