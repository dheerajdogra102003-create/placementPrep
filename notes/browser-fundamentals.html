What is a Web Browser?

A web browser is a client-side software application engineered to retrieve, interpret, compile, and visually render hypermedia resources from the World Wide Web or local storage. At its core, the browser acts as a universal runtime environment that translates raw code—HTML documents, Cascading Style Sheets (CSS), JavaScript source files, and binary media assets—into interactive, human-readable graphical interfaces.

In modern web computing, the browser serves as the primary execution surface for Single-Page Applications (SPAs), handling local state management, cryptographic security negotiations (TLS), background network asynchronous caching, client-side routing, and real-time hardware-accelerated 2D/3D graphics compositing via WebGL and WebGPU.

Entity Definition Primary Role Key Examples
Web Browser Client software running on user device Requests, parses HTML/CSS/JS, compiles and paints UI Google Chrome, Microsoft Edge, Mozilla Firefox, Apple Safari
Search Engine Web service accessible via a browser Crawls, indexes, and queries web pages across the internet Google Search, Microsoft Bing, DuckDuckGo
Website Collection of web pages and hosted assets Provides domain-specific content, media, and business logic Wikipedia, PlacementPrep, GitHub, Amazon
Web Server Server program / hardware hosting websites Listens on network ports, processes requests, serves responses Nginx, Apache HTTP Server, Node.js / Express, Caddy

Modern Multi-Process Browser Architecture

Legacy browsers ran everything in a single process. If a single tab experienced an infinite loop or crashed, the entire browser window crashed. Modern browsers (like Chromium-based Chrome/Edge and Safari) utilize a multi-process architecture that isolates functions across distinct OS processes for fault tolerance, security sandboxing, and responsiveness.

⚡

Modern Multi-Process Browser Architecture

🛡️ Process Isolation
Coordinator
🖥️ Browser Process
Manages UI window chrome, URL address bar, tabs lifecycle, bookmarks, and disk I/O
IPC
I/O Tunnel
🌐 Network Process
Handles DNS queries, TCP/TLS handshakes, HTTP/3, CORS checks, and data streams
HTML/CSS
Sandbox
🎨 Renderer Process
One per tab: Executes V8 JS engine, parses DOM & CSSOM, computes style layouts
GPU draw
Hardware
🎮 GPU Process
Hardware acceleration: Composites tile layers, applies 3D transforms, renders pixels
💡 What is Happening?

Instead of running everything in a single fragile thread, modern browsers (Chromium/Blink) isolate responsibilities across separate OS processes communicating via Inter-Process Communication (IPC). If JavaScript inside a tab encounters an infinite loop or crashes, only that individual Renderer Process terminates; your browser window, network downloads, and other tabs stay running.

🎯 Placement Takeaway

Security Trap: The Renderer Process is strictly sandboxed. It has ZERO permission to access the local hard drive, webcam, or network sockets directly. When JavaScript requests a file or network fetch, it must request the Browser/Network process via IPC to mediate the access.

🌍 Real-Life Analogy

Think of a restaurant: The Browser Process is the manager greeting guests at the door; the Network Process is delivery drivers fetching groceries; the Renderer Process is the kitchen preparing individual dishes in a fireproof room; and the GPU Process is the food plating and lighting presentation.

Browser Process
Controls the application window "chrome" (address bar, back/forward buttons, bookmarking). Manages child process lifecycles and coordinates IPC (Inter-Process Communication).
Renderer Process (Sandboxed)
One spawned per tab/site. Executes HTML parsing, CSSOM calculation, JavaScript via V8 engine, and paints layout. Runs in a restricted OS sandbox with zero direct filesystem access.
Network Process
Handles all low-level networking: DNS queries, socket connection pools, TLS negotiation, HTTP cache management, and cookie storage.
GPU Process
Isolated process dedicated to communicating with graphics hardware. Handles CSS 3D transforms, WebGL shaders, video acceleration, and layer compositing.

Anatomy of a URL (Uniform Resource Locator)

A URL is a structured string that specifies both the identity of a web resource and the precise network mechanism used to retrieve it. Consider the complete corporate URL:

URL ANATOMY SPECIFICATION
https://example.com:443/products?id=25&category=tech#reviews
Segment Sample Value Technical Purpose
Scheme / Protocol https Identifies protocol (HTTP, HTTPS, FTP, WebSocket wss). Determines default port (HTTP=80, HTTPS=443).
Host / Domain example.com The human-readable domain name resolving to server IP address via DNS.
Port :443 Transport layer TCP socket identifier. Optional if standard protocol default (80 or 443).
Path /products Hierarchical path to specific resource or API route on the web server.
Query Parameters ?id=25&category=tech Key-value pairs preceded by ? and delimited by & for filtering, pagination, or state.
Fragment / Hash #reviews Client-side anchor identifying section ID. CRITICAL: Never transmitted to the server in HTTP requests!

URI vs URL vs URN Explained

Interviewers frequently probe whether a fresher understands the Venn diagram relationship between URI, URL, and URN:

Concept Formal Meaning What It Tells You Real-World Example
URI (Superset) Uniform Resource Identifier Identifies a resource by location, name, or both urn:isbn:0451450523 or https://example.com
URL (Subset) Uniform Resource Locator Identifies a resource AND how to reach it https://placementprep.in/notes/browser
URN (Subset) Uniform Resource Name Identifies a resource persistently by name, no location urn:isbn:978-3-16-148410-0 (Book ISBN number)
⚠️ Placement Exam Trap: URI vs URL TCS & Cognizant Favorite
Students mistakenly say that URL and URI are two competing protocols.
✅ Placement Truth: Every URL is a URI, but not every URI is a URL! Think of URI as "Official ID", URL as "Street Address", and URN as "Passport / SSN Number".

DNS (Domain Name System) Deep-Dive

Computers route internet traffic using binary IP addresses (IPv4: 93.184.216.34, IPv6: 2606:2800:220:1...). Humans navigate using memorizable string names (example.com). DNS is the distributed, hierarchical database system that translates alphanumeric domain names into machine-routable IP addresses.

DNS queries utilize UDP port 53 for standard resolution (fast, low-overhead single packet exchange) and fallback to TCP port 53 for large responses (>512 bytes) or zone transfers.

DNS Record Full Name What It Maps Example Use Case
A Address Record Domain name to 32-bit IPv4 address placementprep.in -> 104.21.45.12
AAAA IPv6 Address Record Domain name to 128-bit IPv6 address placementprep.in -> 2606:4700::6815:2d0c
CNAME Canonical Name Alias domain to another true canonical domain www.example.com -> example.com
MX Mail Exchange Domain to incoming mail servers with priority mail.google.com (Priority 10)
NS Name Server Delegates DNS zone to authoritative servers ns1.cloudflare.com
TXT Text Record Arbitrary human/machine-readable metadata SPF records (prevent email spoofing), DKIM, site verification

DNS Resolution Flowchart (Step-by-Step)

When a user requests a domain that has not been recently visited, the DNS lookup traverses a hierarchical chain. If any caching tier contains a valid unexpired record (based on TTL — Time To Live), it short-circuits and immediately returns the IP!

🔍 Recursive vs Iterative DNS Lookup Traversal
01 Browser Cache Browser checks internal memory table (caches DNS lookups for 1–10 minutes). If found, returns IP immediately.
02 OS Cache & Hosts File Operating System checks local DNS cache (viewable via ipconfig /displaydns) and static /etc/hosts.
03 Recursive Resolver Query leaves device to ISP or Public Resolver (e.g. 8.8.8.8 or 1.1.1.1). Resolver checks its cached database.
04 Root DNS Servers If resolver lacks cache, queries 1 of 13 global Root Servers (A through M). Root responds: "Ask the .com TLD server".
05 TLD Nameservers Resolver queries .com TLD server. TLD responds: "Ask authoritative nameservers ns1.cloudflare.com".
06 Authoritative Server Holds the official DNS zone records for the domain. Returns the exact IP address (e.g. 93.184.216.34) to resolver.
07 Client Connects Resolver caches IP for duration of TTL and delivers IP to browser. Browser initiates TCP three-way handshake.
09

Real-Life DNS Interview Scenario

🚨
Accenture / Capgemini Interview Classic

"The website opens when entering its raw IP, but fails when using its domain name. What is wrong?"

User can ping 93.184.216.34 successfully, but typing example.com results in ERR_NAME_NOT_RESOLVED.

1. Root Cause Analysis
Since direct IP connection works, network routing, physical cables, firewalls, and the web server are 100% operational. The failure is strictly within the DNS Resolution Layer.
2. Diagnostic Steps
Run nslookup example.com or dig example.com in terminal to see if DNS returns an IP. Run ipconfig /flushdns to clear stale local cache.
3. Likely Causes
Expired domain registration; missing 'A' record on authoritative DNS; corrupted ISP resolver cache; or malicious hijacking in local hosts file.
4. Interview Takeaway
"DNS translates names to IPs. If IP works but domain fails, the issue is DNS, never server hardware or network connectivity!"

HTTP (Hypertext Transfer Protocol) Fundamentals

HTTP is an application-layer request-response communication protocol operating over TCP/IP (port 80 for HTTP, port 443 for HTTPS). It is fundamentally stateless: each request-response transaction is completely independent; the server does not natively remember previous interactions from the same client without auxiliary state mechanisms (cookies, tokens, sessions).

🔄

The Stateless HTTP Request → Response Exchange

📡 Client-Server Lifecycle
🌐 Client (Browser)
🖥️ Web Server (Backend/Nginx)
1. HTTP Request: GET /products HTTP/1.1
⚙️ Server processes query, verifies auth, serializes JSON/HTML...
2. HTTP Response: HTTP/1.1 200 OK (Content-Type: application/json)
💡 What is Happening?

HTTP is inherently stateless: each request sent by the client is completely self-contained. The server evaluates headers and query params, performs business logic, and streams back the status code and payload without remembering past interactions unless explicit tokens or session cookies are attached.

🎯 Placement Takeaway

Viva Question: "How do websites remember users if HTTP is stateless?" Answers: Cookies (auto-attached via Cookie header), LocalStorage / SessionStorage, or Bearer Tokens in the Authorization header!

🌍 Real-Life Analogy

Ordering at a busy fast-food counter: the cashier takes your order, gives you your burger, and immediately forgets your face for the next customer unless you show your receipt ticket (token/cookie).

HTTP Request Anatomy

Every HTTP request sent by a browser follows a strict plain-text specification consisting of 3 parts:

RAW HTTP/1.1 REQUEST
POST /api/v1/auth/login HTTP/1.1
Host: api.placementprep.in
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/122.0
Content-Type: application/json
Content-Length: 48
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1Ni...

{"username": "candidate_101", "password": "****"}
1. Request Line
METHOD /path HTTP/VERSION (e.g. POST /api/v1/auth/login HTTP/1.1). Sets intent, resource endpoint, and protocol dialect.
2. Request Headers
Key-value metadata pairs. Host (mandatory in HTTP/1.1), User-Agent, Content-Type, Authorization, and Cookie.
3. Empty Line CRLF
Mandatory carriage return line feed (\r\n) signaling to the server that header parsing is complete.
4. Request Body
Optional data payload carrying JSON, XML, or multi-part binary file uploads (primarily used in POST, PUT, PATCH).

HTTP Methods: Safe vs Idempotent

In fresher recruitment exams, interviewers frequently test the mathematical properties of HTTP methods: Safe (read-only, does not alter server state) and Idempotent ($f(f(x)) = f(x)$, making 1 request produces the same server state as 1,000 identical requests).

Method Typical Purpose Safe? Idempotent? Has Body?
GET Retrieve resource representation without side effects ✅ Yes ✅ Yes ❌ No (URL params only)
POST Create a new subordinate resource or submit form data ❌ No ❌ No ✅ Yes
PUT Replace an entire target resource completely ❌ No ✅ Yes ✅ Yes
PATCH Apply partial modifications to an existing resource ❌ No ❌ No (typically) ✅ Yes
DELETE Remove the specified target resource ❌ No ✅ Yes Optional
HEAD Identical to GET, but returns headers ONLY (no body) ✅ Yes ✅ Yes ❌ No
OPTIONS Queries supported HTTP methods / CORS preflight ✅ Yes ✅ Yes ❌ No

HTTP Status Codes Guide & Exam Traps

Status codes are 3-digit integers categorized by their first digit:

Code Status Name Category Real-World Technical Context
200 OK 2xx Success Standard response for successful GET, PUT, or POST requests.
201 Created 2xx Success Resource successfully created via POST. Returns Location header.
204 No Content 2xx Success Action succeeded, but response intentionally has no body (common in DELETE).
301 Moved Permanently 3xx Redirection Resource has a permanent new URL. Browsers cache redirect; search engines transfer SEO.
302 Found (Temp Redirect) 3xx Redirection Temporary redirect. Client should continue using original URL in future requests.
304 Not Modified 3xx Redirection Cached copy is still fresh! Server sends headers only; browser reuses local cache.
400 Bad Request 4xx Client Error Malformed syntax, invalid JSON body, or missing required payload parameters.
401 Unauthorized 4xx Client Error Unauthenticated! Missing, expired, or invalid login credentials / JWT token.
403 Forbidden 4xx Client Error Unauthorized! Identity is known, but user lacks permission/role to access resource.
404 Not Found 4xx Client Error The requested URI path does not exist on the server.
405 Method Not Allowed 4xx Client Error Endpoint exists, but HTTP method is rejected (e.g. POST on a read-only endpoint).
429 Too Many Requests 4xx Client Error User exceeded rate limits (throttled by API gateway).
500 Internal Server Error 5xx Server Error Unhandled exception or crash in backend server code.
502 Bad Gateway 5xx Server Error Proxy/Reverse Proxy (Nginx) received an invalid response from upstream backend.
503 Service Unavailable 5xx Server Error Server is temporarily overloaded or undergoing scheduled maintenance.
504 Gateway Timeout 5xx Server Error Proxy/Load Balancer timed out waiting for upstream server to finish computing.
⚠️ Placement Exam Trap: 401 vs 403 Extremely Common
Students frequently confuse 401 Unauthorized with 403 Forbidden.
✅ Placement Truth: 401 means "Who are you? Log in first!" (Authentication failure). 403 means "I know who you are, but you don't have permission to be here!" (Authorization failure). Logging in again will NEVER fix a 403!

HTTP vs HTTPS

HTTPS (Hypertext Transfer Protocol Secure) is HTTP executed over an encrypted cryptographic transport layer: TLS (Transport Layer Security), previously known as SSL. HTTPS operates on default TCP port 443 (compared to HTTP's port 80).

🛡️

HTTP Plaintext vs HTTPS TLS Encrypted Transport

🔐 Cryptographic Tunnel
❌ HTTP (Port 80) — Cleartext Vulnerability Plaintext Exposure
Client Browser
GET /login?pwd=secret123
Public Wi-Fi / Sniffer
✅ HTTPS (Port 443) — TLS Symmetric Cipher Tunnel AES-256-GCM Scrambled
Client Browser
a8f93b01c7d2e4... (Ciphertext)
Origin Server
💡 What is Happening?

In cleartext HTTP, raw passwords, session cookies, and request URLs are sent as unencrypted ASCII across network cables, allowing any intermediate router or Wi-Fi packet sniffer to eavesdrop. HTTPS wraps HTTP inside an encrypted TLS session tunnel, transforming bytes into unreadable ciphertext.

🎯 Placement Takeaway

Exam Trap: HTTPS provides three distinct security guarantees: Confidentiality (encryption prevents eavesdropping), Integrity (HMAC prevents packet tampering), and Authentication (CA certificates verify server identity).

🌍 Real-Life Analogy

Sending data via HTTP is like mailing an open postcard where the postman, courier, and anyone who glances at it can read every word. HTTPS is like locking the letter inside a titanium briefcase that only the intended recipient possesses the key to unlock.

1. Confidentiality (Encryption)
Data in transit is encrypted using symmetric session ciphers (AES-GCM / ChaCha20). Eavesdroppers cannot read credentials, credit cards, or URLs.
2. Integrity (Tamper-Proof)
Message Authentication Codes (MAC / HMAC) guarantee that packets cannot be altered or injected with malicious ads/scripts during transmission without detection.
3. Authentication (Identity)
Digital certificates issued by trusted Certificate Authorities (CAs) prove the client is actually talking to google.com, not a DNS-spoofed imposter.
⚠️ Placement Exam Trap: Does HTTPS Mean the Site is Safe? Very Common Misconception
Students often answer: "Yes, HTTPS means the website is safe, trustworthy, and free from malware."
✅ Placement Truth: ABSOLUTELY FALSE! HTTPS only guarantees that your connection to the server is encrypted and that the domain matches the certificate. A phishing website or criminal scammer can easily obtain a free SSL certificate (e.g. from Let's Encrypt). HTTPS encrypts traffic; it does NOT validate the moral intent or safety of the website!
16

TLS Handshake (High-Level Overview)

In interview discussions, you should explain why HTTPS uses both Asymmetric and Symmetric encryption:

🔑 Why Two Types of Encryption?

Asymmetric Encryption (Public/Private Key) is mathematically secure but computationally slow. Symmetric Encryption (single shared secret key) is blazing fast. Therefore, the browser uses Asymmetric Encryption for 1 second during the initial TLS Handshake to securely exchange a secret symmetric key. Once exchanged, all actual webpage data is transmitted using fast Symmetric Encryption!

01 Client Hello Browser sends supported TLS versions (TLS 1.2 / 1.3), cipher suites, and a client random string.
02 Server Hello + Certificate Server chooses cipher suite, sends server random, and presents its SSL/TLS Certificate (containing its Public Key).
03 Certificate Validation Browser verifies certificate against pre-installed OS Root Certificate Authorities (checks signature, domain match, expiration).
04 Session Key Derivation Client & server compute a shared symmetric session key (via Diffie-Hellman Key Exchange in TLS 1.3).
05 Encrypted Transmission All subsequent HTTP requests & responses are encrypted end-to-end with the shared symmetric session key.

Cookies & Lifecycle Management

A Cookie is a small snippet of data (maximum ~4KB per cookie) that a web server asks the client browser to store locally and automatically transmit back with future HTTP requests directed to that same origin/domain. Cookies are the original mechanism used to introduce statefulness to the stateless HTTP protocol.

🍪 Cookie Set & Echo Lifecycle
1. Client logs in:        POST /login  ──────►  Server verifies credentials
2. Server sets cookie:    HTTP 200 OK  ◄──────  Set-Cookie: session_id=xyz89; Secure; HttpOnly
3. Browser stores cookie: (Saves to client disk / RAM storage table)
4. Future requests:       GET /profile ──────►  Cookie: session_id=xyz89 (Auto-attached!)
Session Cookies
Lacks an Expires or Max-Age attribute. Retained in RAM memory and deleted as soon as the browser instance or tab is closed.
Persistent Cookies
Explicitly defines Expires=Wed, 21 Oct 2026 07:28:00 GMT or Max-Age=31536000. Written to disk and persists across browser reboots.
18

Critical Cookie Security Flags (HttpOnly, Secure, SameSite)

In modern web development and placement interviews, properly configuring cookie security flags is mandatory to protect against XSS (Cross-Site Scripting) and CSRF (Cross-Site Request Forgery):

PRODUCTION-SECURED SET-COOKIE HEADER
Set-Cookie: auth_token=jwt_998877; Path=/; Secure; HttpOnly; SameSite=Strict
Attribute What It Enforces Attack It Mitigates Placement Key Takeaway
Secure Browser will ONLY transmit this cookie over encrypted HTTPS connections; never over plaintext HTTP. Man-in-the-Middle (MitM) packet sniffing over open public Wi-Fi. Always required in production for authenticated sessions.
HttpOnly Blocks client-side JavaScript APIs (e.g. document.cookie) from reading or accessing the cookie value. XSS (Cross-Site Scripting) session token theft. If an attacker injects a script tag, document.cookie will NOT reveal HttpOnly session cookies!
SameSite=Strict Cookie is NEVER sent with cross-site requests, even when following a link from an external site. CSRF (Cross-Site Request Forgery) attacks. Highest security level; ideal for sensitive banking/e-commerce endpoints.
SameSite=Lax Default in modern Chrome. Cookie is withheld on cross-site subrequests (images, iframes), but sent on top-level safe GET navigations. CSRF while preserving user convenience when clicking incoming external links. Standard default policy across modern web browsers.
SameSite=None Cookie sent on all cross-site requests. Requires Secure flag to be accepted! Used for third-party embeds (widgets, tracking). Modern browsers reject SameSite=None if not paired with Secure.

Browser Caching & The 304 Not Modified Protocol

Network round trips over mobile networks introduce latency (50ms–300ms). The browser cache stores static assets (CSS, JS bundles, company logos, fonts) locally on disk or memory so subsequent page loads can skip network downloads.

Cache-Control: max-age=31536000, immutable
Tells the browser: "Store this asset for 1 year. Do NOT even make a network request to check; serve directly from disk!" Used for version-hashed assets (bundle.a8f9.js).
Cache-Control: no-cache
Does NOT mean "do not cache"! It means: "Cache the file, but you MUST validate with the server (via ETag) before using it!"
Cache-Control: no-store
The TRUE "do not cache" directive. The browser must never write any copy of this response to disk/RAM (used for sensitive financial ledgers).
⚡ How 304 Not Modified Works (Conditional GET)
Initial Request:
Client ────────► GET /style.css
Client ◄──────── HTTP 200 OK + ETag: "v1.2" + [500KB CSS Payload] (Browser saves to disk cache)

Subsequent Request:
Client ────────► GET /style.css + Header: [If-None-Match: "v1.2"]
Server checks:   (Calculates file hash. Has style.css changed? NO!)
Server ◄──────── HTTP 304 Not Modified (EMPTY BODY, zero CSS bytes transferred!)
Browser action:  Instantly loads the 500KB stylesheet from local SSD in 1 millisecond!

Web Storage: LocalStorage Deep-Dive

Introduced in HTML5, LocalStorage provides a synchronous, origin-bound key-value storage engine in the browser with an industry-standard capacity of ~5MB to 10MB per origin (compared to cookies' tiny 4KB limit). Data stored in LocalStorage has no expiration date; it persists indefinitely across browser restarts, OS reboots, and tabs until explicitly cleared by JavaScript or manual user cache clearing.

LOCALSTORAGE SYNTAX CHEAT SHEET
// Store string data
localStorage.setItem('theme', 'dark');

// Store objects (MUST serialize to JSON string!)
const user = { id: 101, name: 'Nitin' };
localStorage.setItem('user_profile', JSON.stringify(user));

// Retrieve data
const theme = localStorage.getItem('theme'); // 'dark'
const profile = JSON.parse(localStorage.getItem('user_profile'));

// Remove single key or clear all origin data
localStorage.removeItem('theme');
localStorage.clear();

⚠️ Are LocalStorage Values Sent with HTTP Requests?

A high-yield frontend web architecture question:

  • HTTP Cookies (~4 KB): Automatically transmitted in the Cookie: header with EVERY single HTTP request to that domain (including images and CSS). Great for auth session IDs, terrible for storing large data.
  • localStorage (~5-10 MB): Stored purely on the client machine; NEVER automatically sent to the server. Persists indefinitely until cleared via JavaScript or user cache reset.
  • sessionStorage (~5 MB): Client-only; strictly scoped to the single browser tab. Closing the tab immediately destroys the data.
🎯 Key Takeaway: Cookies travel with every HTTP header (4KB). LocalStorage stays in the browser across restarts (10MB). SessionStorage dies when the tab closes.
🏢 E-Commerce Multi-Tab Shopping Cart
Amazon / Flipkart
A user's authentication token is stored in an HttpOnly, Secure cookie to prevent XSS theft. Their active shopping cart draft is preserved in localStorage so items survive browser restarts, while single-session checkout steps live in sessionStorage.
❓ Quick Placement Check

If a user opens the exact same web app in two different tabs of the same browser window, do both tabs share the same sessionStorage?

Answer: NO. sessionStorage is strictly scoped to the unique tab/window browsing context. Opening the same URL in a new tab initializes a completely new, independent sessionStorage instance.

CSSOM (CSS Object Model) Construction

While constructing the DOM, the browser encounters CSS <link> stylesheets and <style> blocks. The CSS parser transforms these rules into a hierarchical tree called the CSSOM (CSS Object Model).

CSS is render-blocking: The browser will NOT begin painting pixels on screen until the complete CSSOM has been constructed, because rendering an unstyled page (Flash of Unstyled Content - FOUC) would disorient users and cause costly layout reflows!

SVG Vector Diagram
⚠️ Reflow (Layout) vs Repaint: Performance Trap

The #1 Web Performance & UI Developer interview test:

  • 1. DOM + CSSOM Construction: HTML builds DOM tree; CSS builds CSSOM tree. CSS is render-blocking!
  • 2. Render Tree: Combines visible DOM elements with CSSOM styles (skips display: none elements!).
  • 3. Layout (Reflow): Calculates the exact geometric dimensions and x/y screen coordinates. Extremely expensive!
  • 4. Paint (Rasterize): Fills pixels (colors, borders, shadows) onto layers.
  • Placement Trap: Changing width or font-size triggers an expensive Reflow + Repaint. Changing opacity or transform runs purely on the GPU compositor, causing zero reflow!

Web optimization engineers improve Interaction to Next Paint (INP) by animating UI cards using CSS transform: translate3d() instead of modifying top/left margin styles, avoiding layout reflows and running animations at 60 FPS on mobile GPUs.
❓ Quick Placement Check

Does an element with CSS 'display: none' get included in the browser's Render Tree?

Answer: NO. Elements with 'display: none' exist in the DOM tree, but are completely omitted from the Render Tree because they take up zero visual geometry and no pixels on screen (unlike 'visibility: hidden', which remains in the Render Tree).

01 DOM Construction HTML parser converts HTML tags into the Document Object Model (DOM) tree.
02 CSSOM Construction CSS parser processes stylesheets and cascades inheritance into the CSS Object Model (CSSOM) tree.
03 Render Tree Creation Combines visible DOM nodes with their matching CSSOM styles. Excludes display: none and <head> (includes visibility: hidden).
04 Layout (Reflow) Calculates the exact geometric coordinates, width, height, and device viewport positioning of every box.
05 Paint (Rasterization) Converts geometric boxes into actual screen pixels (rasterizing colors, text fonts, borders, box shadows).
06 Compositing GPU draws multiple independent layers in correct z-index order and composites them to physical monitor pixels.

The Browser Event Loop (Placement Level)

JavaScript is single-threaded: it possesses only ONE call stack and executes one statement at a time. Yet, the browser can perform non-blocking AJAX network requests, user click tracking, and audio playback concurrently. How? Through the Event Loop!

🔄 The Browser Event Loop & Microtask Priority Architecture Call Stack • Web APIs • Microtasks • Macrotasks
📚 CALL STACK (Single JS Thread)
LIFO execution • Synchronous run-to-completion frames.
🌐 BROWSER WEB APIs (C++ Threads)
DOM Events, setTimeout countdowns, fetch() network calls.
↓ Async Callbacks Queued by Priority ↓
⚡ Priority 1: MICROTASK QUEUE (Drained Completely!) Immediate
Promise.then(), Promise.catch(), async/await resume, queueMicrotask(), MutationObserver.
⏳ Priority 2: MACROTASK QUEUE (One Task Per Tick!) Scheduled
setTimeout(), setInterval(), setImmediate(), UI click events, I/O callbacks.
💡 What is happening?
The Event Loop continuously monitors the Call Stack. The millisecond the Call Stack is empty, it drains the ENTIRE Microtask queue before picking a single task from the Macrotask queue.
🎯 Remember for Exams
Promise.resolve().then(...) ALWAYS executes BEFORE setTimeout(..., 0)! Microtasks have absolute priority over timers and macrotasks in placement tracing questions.
🌍 Real-Life Example
At a doctor's clinic: Scheduled general checkup patients wait in line (Macrotask Queue), but if an ambulance emergency arrives (Microtask Queue), the doctor sees ALL emergency cases before calling the next scheduled patient!
CLASSIC PLACEMENT TRACING QUESTION
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

Promise.resolve().then(() => {
  console.log('3');
});

console.log('4');
🎯 Trace Execution Output: 1, 4, 3, 2

1. Synchronous statements execute immediately on the Call Stack: '1' then '4'.
2. setTimeout callback is pushed to the Macrotask Queue.
3. Promise.then callback is pushed to the Microtask Queue.
4. Call stack empties. The Event Loop prioritizes and drains the Microtask Queue first, logging '3'.
5. Finally, the Event Loop takes the first item from the Macrotask Queue, logging '2'.

The Same-Origin Policy (SOP)

The Same-Origin Policy is the fundamental cornerstone of modern web browser security. It dictates that a script executing on one webpage origin cannot read or interact with sensitive resources (DOM, cookies, AJAX responses) originating from a different origin.

An Origin is strictly defined by the three-tuple: Protocol + Host + Port. If ANY of these three values differ, it is classified as Cross-Origin!

Compared URL to https://example.com:443/app Same Origin? Reason
https://example.com/products ✅ YES Protocol (https), Host (example.com), and Port (443 implicit) match exactly. Path can differ freely.
http://example.com/app ❌ NO Different Protocol (http vs https).
https://api.example.com/app ❌ NO Different Host (subdomain api.example.com vs example.com).
https://example.com:8080/app ❌ NO Different Port (:8080 vs :443).

CORS (Cross-Origin Resource Sharing)

Modern architectures decouple frontend React apps (http://localhost:3000) from backend REST APIs (https://api.company.com). Because they have different origins, the browser blocks the frontend from reading the API response due to the Same-Origin Policy!

CORS is an HTTP header-based mechanism that allows a server to explicitly declare to the client browser: "I authorize scripts from origin X to read my data!"

SERVER-SIDE CORS RESPONSE HEADERS
// Authorize specific origin (never use * with credentials!)
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true
⚠️ Placement Exam Trap: Who Enforces CORS? Top Interview Question
Students often answer: "The backend server blocks the request when CORS fails."
✅ Placement Truth: FALSE! The client browser enforces CORS, not the backend server! If you test the exact same API in Postman or curl, it succeeds 100% because Postman is not a browser and does not enforce the Same-Origin Policy! The server actually processes the request and sends the response, but the browser inspects headers and suppresses the data from client JS!

Web Page Loading — The Complete Journey (Hero Diagram)

Here is the definitive answer to the ultimate placement interview question: "Explain everything that happens from the moment a user types a URL and presses Enter until the webpage is completely displayed on screen."

01 URL Parsing & Protocol Check Browser parses the string into protocol, domain, port, and path. If protocol is missing, defaults to HTTPS.
02 HSTS & Local Cache Inspection Checks HSTS preload list to force HTTPS. Checks browser HTTP cache for valid, unexpired responses (Cache-Control).
03 DNS Resolution Hierarchy Checks Browser Cache -> OS Cache -> Local DNS Resolver -> Root -> TLD -> Authoritative server to obtain target IP.
04 TCP Three-Way Handshake Browser establishes reliable TCP connection on port 443 via SYN -> SYN-ACK -> ACK packet sequence.
05 TLS Cryptographic Handshake Client & server validate digital certificates, exchange public keys via Diffie-Hellman, and derive shared symmetric session keys.
06 HTTP Request Transmission Browser encrypts and transmits GET / HTTP/1.1 with request headers (Host, User-Agent, Cookie).
07 Server Processing & Response Web server (Nginx/Node) processes request, queries database, generates HTML stream, and returns HTTP/1.1 200 OK.
08 DOM Construction & Tokenization Renderer process parses raw HTML byte stream into tokens and constructs the DOM Tree.
09 CSSOM Construction Browser fetches external stylesheets and parses CSS rules into the render-blocking CSSOM Tree.
10 Render Tree Assembly DOM and CSSOM are merged into the Render Tree containing only visible nodes (excludes display: none).
11 Layout (Reflow) Browser calculates exact viewport pixel coordinates, geometry, width, and height for each render node.
12 Painting & GPU Compositing Rasterizer paints visual pixels into bitmap memory. GPU composites layers and presents the interactive page on screen!

Top 20 Common Placement Exam Traps

Master these 20 high-frequency traps to avoid falling into standard recruiter trick questions:

1. DNS ≠ Content Transfer
DNS only resolves domain names to IP addresses. It transfers zero HTML, CSS, or webpage content!
2. HTTPS ≠ Moral Trustworthiness
HTTPS guarantees encrypted transport and domain identity. Scammers and malware sites routinely have valid SSL certificates!
3. 401 vs 403 Are Not Synonyms
401 means unauthenticated (must log in). 403 means unauthorized (logged in, but forbidden from resource).
4. 404 ≠ Server is Down
404 proves the web server is healthy and responding! It only means the specific file/route requested is absent.
5. Fragment (#hash) Never Sent to Server
In https://site.com/page#top, the #top is parsed client-side by browser. The server never receives #top!
6. Incognito ≠ Anonymity
Incognito wipes local SSD history upon window close. Your ISP, university Wi-Fi, and server logs still record all requests!
7. DOM ≠ HTML Source Text
HTML source is static raw text. The DOM is the live dynamic memory tree modified by JavaScript and error-corrected by the parser.
8. JS Engine ≠ Browser Web APIs
V8 only provides the ECMAScript spec. fetch(), document, and setTimeout() are C++ APIs provided by the browser!
9. Browser Enforces CORS, Not Server
The server processes the request and responds. The client browser inspects response headers and blocks client JS from reading it.
10. display: none vs visibility: hidden
display: none is completely excluded from the Render Tree. visibility: hidden IS in the Render Tree and consumes layout space!
11. LocalStorage is Synchronous
LocalStorage operations block the main UI thread. Reading or writing megabytes of data will cause visible UI stutter!
12. Cookies Are Limited to ~4KB
Do not attempt to store large datasets in cookies. Exceeding 4KB causes servers to reject headers with HTTP 431.
13. Microtasks Beat Macrotasks
Promise .then() callbacks run immediately when call stack empties, BEFORE any setTimeout() callbacks!
14. Cache-Control: no-cache Permits Caching
no-cache stores the file locally, but forces server revalidation via ETag before reuse. no-store forbids caching!
15. HttpOnly Protects Cookies from XSS
Marking a cookie HttpOnly prevents document.cookie access, neutralizing cookie theft via script injection.
16. CSS is Render-Blocking
Browsers will not paint any pixels until the full CSSOM is built to prevent Flash of Unstyled Content (FOUC).
17. Port Numbers Define Origin
http://localhost:3000 and http://localhost:8080 are strictly DIFFERENT origins governed by CORS!
18. SessionStorage Does Not Share Across Tabs
Opening a new tab to the same URL creates a fresh, isolated SessionStorage context!
19. 304 Responses Have Zero Body
HTTP 304 Not Modified contains headers only. The browser loads the body from local disk cache, saving bandwidth.
20. GET Requests Must Be Idempotent
Never execute database deletions or fund transfers via GET requests. Browsers, crawlers, and proxies prefetch GET links!

25 Browser Interview Questions & Model Answers

Master these categorized technical interview questions commonly posed by recruiters at TCS, Infosys, Accenture, Cognizant, and Capgemini:

Level 1: Beginner Technical Questions (10)

Q1 What happens when you enter a URL into a browser address bar?
▼
The browser parses the URL, checks cache, resolves domain to IP via DNS, establishes a TCP 3-way handshake on port 443, completes TLS cryptographic handshake, sends an HTTP GET request, receives the HTML stream, builds DOM and CSSOM, merges them into the Render Tree, performs layout (reflow), and paints pixels to screen.
Key Interview Point: Mention DNS -> TCP -> TLS -> DOM/CSSOM -> Render Tree -> Layout -> Paint.
Q2 What is the difference between HTTP and HTTPS?
▼
HTTP sends data in unencrypted plaintext on port 80, vulnerable to packet sniffing. HTTPS executes HTTP over a TLS/SSL encrypted cryptographic tunnel on port 443, ensuring confidentiality, data integrity, and server authentication via digital certificates.
Key Interview Point: Port 80 vs 443; plaintext vs encrypted TLS tunnel; Certificate Authority validation.
Q3 What is DNS and why is it called the phonebook of the internet?
▼
DNS (Domain Name System) translates human-readable domain names (like google.com) into 32-bit/128-bit machine-routable IP addresses (like 142.250.190.46). Just as a phonebook maps names to phone numbers, DNS maps hostnames to IP addresses over UDP port 53.
Key Interview Point: Translates string names to binary routing IP addresses; operates primarily over UDP port 53.
Q4 What is the difference between a Cookie, LocalStorage, and SessionStorage?
▼
Cookies are ~4KB string tokens sent automatically with matching HTTP requests to manage sessions. LocalStorage is ~5-10MB client-side persistent storage that never expires. SessionStorage is ~5MB client-side storage isolated to a single tab that deletes when the tab closes.
Key Interview Point: Cookies sent with HTTP requests; LocalStorage persists; SessionStorage tab-isolated.
Q5 What is the DOM in web browsers?
▼
The Document Object Model (DOM) is an in-memory, language-independent tree representation of an HTML document created by the browser parser. It allows JavaScript to dynamically query, traverse, and mutate elements, attributes, and styles.
Key Interview Point: Tree structure representing HTML nodes in memory; accessible via JavaScript.
Q6 What is the difference between GET and POST requests?
▼
GET is safe and idempotent, passing parameters in the URL query string to retrieve resources without modifying server state. POST is neither safe nor idempotent, passing data payloads inside the request body to create resources or submit forms.
Key Interview Point: Safe/idempotent vs modifying state; URL query string vs Request Body.
Q7 What does HTTP status code 404 mean?
▼
HTTP 404 Not Found is a client-side error indicating that the client successfully reached the web server, but the server could not locate any active resource or routing handler corresponding to the requested URI path.
Key Interview Point: Proves server is healthy and responding, but requested path does not exist.
Q8 What is the difference between textContent and innerHTML?
▼
textContent sets raw text without parsing HTML tags, making it safe from Cross-Site Scripting (XSS). innerHTML parses strings as HTML elements, executing any embedded tags or scripts and creating security vulnerabilities if untrusted input is displayed.
Key Interview Point: textContent prevents XSS; innerHTML parses tags and risks script injection.
Q9 What does the Same-Origin Policy (SOP) enforce?
▼
The Same-Origin Policy prevents client-side scripts loaded from one origin from accessing or reading cookies, DOM nodes, or AJAX response data from a different origin. An origin is strictly defined by the tuple: Protocol, Host, and Port.
Key Interview Point: Origin = Protocol + Host + Port. Prevents malicious sites from stealing session data.
Q10 What is browser caching and why is it important?
▼
Browser caching stores static assets (CSS, JS, images) locally on user disk or RAM. On subsequent visits, the browser loads resources instantly without network overhead, dramatically reducing server bandwidth and page loading latency.
Key Interview Point: Saves local copies of assets; governed by Cache-Control and ETag headers.

Level 2: Intermediate Technical Questions (10)

Q11 Explain the difference between HTTP 401 Unauthorized and HTTP 403 Forbidden.
▼
401 Unauthorized indicates an **Authentication** failure: credentials are missing or invalid, and logging in can grant access. 403 Forbidden indicates an **Authorization** failure: the user identity is known and authenticated, but the user lacks sufficient permission/role to access the resource.
Key Interview Point: 401 = Who are you? (AuthN); 403 = You lack permission (AuthZ).
Q12 How does HTTP 304 Not Modified optimize web performance?
▼
When an asset's cache expires, the client sends a conditional request with If-None-Match: "ETag". If the file has not changed on the server, the server replies with 304 Not Modified with an empty body, allowing the browser to reuse the local cached copy with zero payload download.
Key Interview Point: Conditional GET request with ETag; 304 has empty body; saves bandwidth.
Q13 What are HttpOnly and Secure cookie flags and why are they critical?
▼
Secure ensures the cookie is only transmitted over encrypted HTTPS connections, preventing plaintext sniffing. HttpOnly blocks client-side JavaScript (document.cookie) from reading the cookie, mitigating session token theft via Cross-Site Scripting (XSS).
Key Interview Point: Secure = HTTPS only; HttpOnly = JavaScript cannot read (prevents XSS session hijacking).
Q14 What is the difference between display: none and visibility: hidden in rendering?
▼
display: none removes the element completely from the **Render Tree**, meaning it takes zero layout space and triggers a reflow when toggled. visibility: hidden keeps the element in the Render Tree, preserving its layout width and height on screen while painting it transparent.
Key Interview Point: display: none is excluded from Render Tree; visibility: hidden consumes layout space.
Q15 How does the JavaScript Event Loop handle microtasks vs macrotasks?
▼
When the call stack empties, the Event Loop drains the **Microtask Queue** (Promise handlers, queueMicrotask) completely until empty before processing a single task from the **Macrotask Queue** (setTimeout, setInterval, I/O events). Microtasks always take priority!
Key Interview Point: Microtasks (Promises) are drained completely before each Macrotask (setTimeout).
Q16 What is CORS and why does a browser send a Preflight OPTIONS request?
▼
CORS is a browser mechanism that relaxes SOP using response headers. For "non-simple" requests (custom headers like Authorization, or methods like PUT/DELETE), the browser automatically sends an HTTP OPTIONS preflight request to confirm whether the server permits the operation before sending the actual request.
Key Interview Point: Preflight OPTIONS checks server permissions before executing non-simple cross-origin requests.
Q17 What is the difference between Reflow (Layout) and Repaint?
▼
**Reflow (Layout)** recalculates the geometry, dimensions, and positioning of nodes in the document, which is computationally expensive. **Repaint** occurs when visual properties that don't affect geometry (like color or background-color) change, rasterizing new pixels without recalculating dimensions.
Key Interview Point: Reflow recalculates geometry/positions (expensive); Repaint redraws colors/pixels (cheaper).
Q18 What are the SameSite cookie attributes (Strict, Lax, None)?
▼
Strict forbids sending cookies on any cross-site request (highest CSRF protection). Lax (default) withholds cookies on cross-site subrequests (images/iframes) but sends them on safe top-level GET navigations. None sends cookies on all cross-site requests (requires Secure).
Key Interview Point: Prevents CSRF. Strict = never cross-site; Lax = top-level GET only; None = requires Secure.
Q19 Why is CSS considered render-blocking while asynchronous JS is not?
▼
CSS is render-blocking because browsers cannot build the Render Tree or calculate layout until the full CSSOM is constructed, preventing Flash of Unstyled Content (FOUC). JavaScript loaded with defer or async downloads in the background without blocking HTML parsing.
Key Interview Point: Prevents FOUC; DOM + CSSOM required for Render Tree before Layout/Paint.
Q20 What is the difference between HTTP 301 and HTTP 302 redirects?
▼
301 Moved Permanently indicates the URL has permanently changed; browsers cache the redirect and search engines transfer SEO ranking to the new target. 302 Found indicates a temporary redirect; browsers do not cache permanently, retaining the original URL for future visits.
Key Interview Point: 301 is permanent & cached (transfers SEO); 302 is temporary and not cached permanently.

Level 3: Senior & Scenario-Based Questions (5)

Q21 Why would an API call succeed in Postman but fail in a React frontend browser app?
▼
Postman is a standalone desktop testing client that does not implement or enforce the browser **Same-Origin Policy (SOP)**. When executed inside a web browser, the browser detects a cross-origin request and blocks client JavaScript from reading the response if the backend lacks CORS headers (Access-Control-Allow-Origin).
Key Interview Point: Postman is not a browser and ignores CORS/SOP. Browsers enforce CORS strictly.
Q22 How does Cache Busting solve the problem of users seeing stale CSS/JS files?
▼
Cache busting appends a unique cryptographic content hash to static asset filenames (e.g. bundle.8f9b2.js). When source code changes, the build tool generates a new filename with a new hash, forcing the browser to fetch the new asset while allowing older assets to use aggressive caching (max-age=31536000).
Key Interview Point: Content hashing changes the URL filename on every deployment, bypassing stale caches.
Q23 What happens if an image is loaded from an HTTP origin on an HTTPS webpage?
▼
This triggers a **Mixed Content** security warning. Modern browsers will either automatically upgrade the image request to HTTPS, or block it entirely (especially for active mixed content like scripts or iframes) to prevent Man-in-the-Middle network tampering.
Key Interview Point: Mixed content vulnerability; browsers block insecure scripts and warn on insecure images.
Q24 Why does script tag placement at the bottom of the body or with 'defer' improve loading speed?
▼
Standard <script> tags block the HTML parser: the browser pauses DOM building while downloading and executing the script. Adding defer downloads the script in parallel without blocking HTML parsing, executing it in order only after DOM construction completes.
Key Interview Point: Prevents HTML parser blocking; defer downloads in parallel and executes after DOM is ready.
Q25 What is the difference between an Authoritative DNS server and a Recursive Resolver?
▼
A **Recursive Resolver** (ISP, Google 8.8.8.8) is the client's agent that hunts down the IP address across root, TLD, and authoritative servers. An **Authoritative Server** (Cloudflare, Route 53) holds the official DNS records configured by the domain owner and provides the definitive IP answer.
Key Interview Point: Recursive resolver hunts and caches; Authoritative server holds official zone records.

Rapid-Fire Placement Mini Quiz (10 MCQs)

Test your mastery immediately! Click any question to reveal the correct answer and technical reasoning:

1. Which component of the URL https://example.com:443/shop?item=shoe#reviews is NEVER transmitted to the server in an HTTP request?
A. Port :443
B. Query parameter ?item=shoe
C. Fragment identifier #reviews
D. Path /shop
Correct Answer: C (#reviews)
The fragment identifier (hash) is processed purely client-side by the browser engine to scroll the viewport to the element with id="reviews". RFC 3986 specifies that fragments are never included in the HTTP request line sent over the wire.
2. What DNS record maps a domain name directly to a 128-bit IPv6 address?
A. A Record
B. AAAA Record
C. CNAME Record
D. NS Record
Correct Answer: B (AAAA Record)
'A' records map to 32-bit IPv4 addresses. 'AAAA' (Quad-A) records map to 128-bit IPv6 addresses (named Quad-A because 128 bits is four times the 32 bits of IPv4).
3. A web user receives HTTP 403 Forbidden. What is the fundamental issue?
A. The user is unauthenticated and must provide login credentials.
B. The user is authenticated, but lacks permission/role to access the resource.
C. The web server process has crashed.
D. The requested URL path does not exist on the server.
Correct Answer: B (Authenticated, but lacks permission)
403 indicates an Authorization failure. The server understands who the user is, but explicitly refuses access due to insufficient privilege. Re-authenticating will not fix 403.
4. Which cookie security attribute blocks client-side JavaScript (document.cookie) from reading its value?
A. Secure
B. HttpOnly
C. SameSite=Strict
D. Max-Age
Correct Answer: B (HttpOnly)
HttpOnly prevents client-side scripts from reading the cookie, neutralizing session token theft via Cross-Site Scripting (XSS).
5. Which of the following elements is EXCLUDED from the browser's Render Tree?
A. An element styled with visibility: hidden
B. An element styled with display: none
C. An element styled with opacity: 0
D. An element positioned off-screen with left: -9999px
Correct Answer: B (display: none)
display: none is completely excluded from the Render Tree. visibility: hidden, opacity: 0, and off-screen elements are included because they affect layout geometry or inherit rendering properties.
6. Under the Same-Origin Policy, which of the following shares the same origin with https://api.test.com:443?
A. http://api.test.com:443
B. https://test.com:443
C. https://api.test.com:8080
D. https://api.test.com/v2/users
Correct Answer: D (https://api.test.com/v2/users)
Origin is defined solely by Protocol (https), Host (api.test.com), and Port (443 implicit). Path does not affect origin!
7. What does the server return when an asset's ETag matches the client's If-None-Match header?
A. HTTP 200 OK with full file body
B. HTTP 204 No Content
C. HTTP 304 Not Modified with empty body
D. HTTP 301 Moved Permanently
Correct Answer: C (HTTP 304 Not Modified)
The server signals that the cached version is still fresh. The browser reuses the local cached asset without transferring payload bytes.
8. What happens to SessionStorage data when a user closes their browser tab?
A. It persists indefinitely until cleared manually.
B. It is immediately deleted and cleared from memory.
C. It is synced to the backend server.
D. It is converted into a cookie.
Correct Answer: B (Immediately deleted)
SessionStorage is strictly bound to the lifetime of the browser tab. Closing the tab wipes all associated data.
9. Which queue does the browser Event Loop prioritize first when the call stack becomes empty?
A. Microtask Queue (Promise handlers, queueMicrotask)
B. Macrotask Queue (setTimeout, setInterval)
C. I/O Queue
D. Garbage Collection Queue
Correct Answer: A (Microtask Queue)
Microtasks (Promise callbacks) are drained completely before the Event Loop fetches a single macrotask from the timer queue.
10. What HTTP method is used by browsers for automated CORS preflight verification?
A. HEAD
B. OPTIONS
C. TRACE
D. CONNECT
Correct Answer: B (OPTIONS)
The browser dispatches an OPTIONS request with Origin and Access-Control-Request-Method headers to query the server's cross-origin permissions before sending non-simple requests.
