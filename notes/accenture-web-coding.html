ACCENTURE WEB CODING ROUND — 5 MINUTE OVERVIEW Actual Reported Pattern

Understanding the exact test environment, skeleton structure, and evaluation mechanism.

The Exact Assessment Format

In recent 2025–2026 on-campus and off-campus drives (reported on Naukri Code360, GeeksforGeeks, and candidate placement debriefs), the frontend coding section gives you a pre-built skeleton webpage (HTML, CSS, and an incomplete or blank JavaScript script). You are not asked to build a full React webapp from scratch. Instead, your task is to wire up requested interactivity and satisfy specific test cases.

Aspect Accenture Exam Reality Fresher Strategy
Environment Embedded web browser editor (split-pane with HTML, CSS, JS tabs + live preview output). Do not write external library CDNs (no jQuery, no React). Rely purely on native Vanilla JS.
Skeleton Code HTML tags already contain predefined ids, classes, and placeholders. Never rename existing IDs or classes! The automated test grader runs DOM selector checks against those exact names.
Common Tasks Button click interactions, dynamic text change, input data transfer into message boxes, simple clocks, counters, and visibility toggles. Follow the 3-step universal rhythm: Select element → Bind event listener → Mutate property/class.
💡
The "Skeleton Rule" That Saves Your Score: Before typing a single line of JavaScript, inspect the HTML tab for 60 seconds. Note down the exact spellings of id="..." and class="...". 90% of zero scores occur because a candidate wrote document.getElementById('msg') when the HTML had id="message"!

🛡️ The 8 Golden Rules of Provided Skeleton Code (Very High Importance)

  1. 1. Read the HTML First: Inspect tag structure and notice which containers already exist.
  2. 2. Identify IDs and Classes: Write down every target id and class precisely as spelled.
  3. 3. Read the Comments in Provided Code: Boilerplate comments often explicitly tell you: /* Write your code here */ or // Function to update display.
  4. 4. Read the CSS: Check if helper classes (like .hidden, .active, or .error) already exist so you can simply toggle them.
  5. 5. Read Existing JavaScript: Observe if functions or variables have already been declared. If a function signature function updateTime() is provided, write your logic inside it!
  6. 6. Modify Only the Required Section: Do not tamper with surrounding markup or styling that wasn't requested.
  7. 7. Avoid Unnecessarily Rewriting the Entire Page: Automated test assertions rely on pre-existing DOM node hierarchies. Rewriting the page will fail all test suites.
  8. 8. Use Existing IDs/Classes/Functions Whenever Possible: Never introduce arbitrary custom IDs if the skeleton already provided them.

Mental model and tree representation required for fast manipulation.

What the DOM is: The Document Object Model (DOM) is a tree-like JavaScript object representation of your HTML document that lets JS read and modify content, structure, and styles in real-time.
🌲

🎯

const btn = document.getElementById('submitBtn');

ELEMENT SELECTION Critical Priority

Targeting nodes accurately in the DOM tree.

1. document.getElementById('idName')
CRITICAL
What it does: Selects and returns the single HTML element matching the given unique ID string, or null if not found.
📝 Syntax & Usage
document.getElementById('heading');
Notice: No '#' symbol used inside getElementById!
⚠️ Common Mistake
Writing getElementById('#myId'). That returns null because getElementById searches raw ID names.
💼 Real-Life Use Inside Script
const clockDisplay = document.getElementById('clock'); clockDisplay.textContent = '12:00:00';
🎯 Accenture Mini Task
Select a paragraph with ID statusMsg and verify it is not null before modifying it.
2. document.querySelector('cssSelector')
CRITICAL
What it does: Returns the first element that matches the specified CSS selector (class, ID, tag, or compound).
📝 Syntax & Usage
document.querySelector('.submit-btn');
document.querySelector('#nav > .active');
⚠️ Common Mistake
Forgetting the dot . for classes or # for IDs. querySelector('btn') searches for a <btn> tag!

Key Difference: querySelector vs getElementById

Feature getElementById('demo') querySelector('#demo')
Argument Prefix Raw string only: 'demo' CSS syntax: '#demo', '.card', 'div > p'
Scope IDs only Any valid CSS selector
Recommendation Best and fastest when selecting a single element with known ID. Essential when selecting by class or complex hierarchy.

CHANGING TEXT Critical Priority

Manipulating visible strings without parsing HTML tags.

element.textContent
PREFERRED IN EXAMS
What it does: Gets or sets the text content of the node and its descendants as plain text, escaping any HTML tags.
Changing Text Example
const title = document.getElementById('titleText');
title.textContent = 'Accenture 2026 Ready!'; // Safely sets visible text
🌟 One-Line Real Life Use
Updating a score counter or live digital clock readout.
⚠️ Common Mistake
Writing title.textContent() = 'text' (it is a property, NOT a function call).

CHANGING HTML High Priority

Injecting HTML markup and understanding innerHTML vs innerText vs textContent.

element.innerHTML
USE WITH CARE
What it does: Gets or sets the HTML markup contained within the element, causing the browser to parse tags into real DOM nodes.
Injecting HTML Markup
const container = document.getElementById('badgeArea');
container.innerHTML = '<span class="badge">Approved ✓</span>';

Comparison: innerHTML vs innerText vs textContent

Property Parses HTML Tags? Respects CSS Hidden Styles? Minimal Example
innerHTML Yes (renders tags) N/A (renders DOM structure) p.innerHTML = '<b>Hi</b>' → renders bold Hi
innerText No (prints as plain text) Yes (ignores hidden elements) p.innerText = '<b>Hi</b>' → renders literal "<b>Hi</b>"
textContent No (prints as plain text) No (reads all text, even hidden) p.textContent = '<b>Hi</b>' → faster, clean string update
💡
Exam Tip: If the task simply asks to update text inside a label, button, or message box, always prefer .textContent. Only use .innerHTML if the question explicitly asks you to insert bold, italics, or list elements.

CHANGING CSS USING JAVASCRIPT Critical Priority

Manipulating inline styles, camelCase rules, and style vs CSS classes.

How it works: Accessing element.style.propertyName writes inline styles directly onto the element. CSS hyphenated properties convert to camelCase in JavaScript.
CSS Property JavaScript Style Property Correct Exam Syntax
background-color backgroundColor elem.style.backgroundColor = '#10b981';
font-size fontSize elem.style.fontSize = '18px'; (always include 'px'!)
display display elem.style.display = 'none'; (or 'block' / 'flex')
text-align textAlign elem.style.textAlign = 'center';
⚠️
Unit Trap: Writing elem.style.width = 200; or elem.style.fontSize = 20; fails silently in browsers! You MUST provide the string unit: elem.style.width = '200px';

style.property vs CSS Class: When to use which?

Approach When to Use in Exam Example
elem.style.property When changing a dynamic individual value (e.g. calculated width, specific random hex color, or simple display toggle). box.style.display = 'none';
elem.classList.add('className') When applying a pre-existing CSS stylesheet rule (e.g. .active, .hidden, .highlight). Preferred whenever skeleton CSS already has classes! box.classList.add('hidden');

CLASSLIST MANIPULATION Critical Priority

add, remove, toggle, contains, and className vs classList.

What classList is: A DOMTokenList object providing clean helper methods (add, remove, toggle, contains) to manipulate an element's classes without overwriting existing ones.
Method Syntax Behavior
classList.add() elem.classList.add('active'); Adds the class if not already present.
classList.remove() elem.classList.remove('active'); Removes the class safely without error if absent.
classList.toggle() elem.classList.toggle('hidden'); Adds if missing; removes if present. (Returns boolean state).
classList.contains() if (elem.classList.contains('active')) Returns true if class exists, otherwise false.

className vs classList: Why classList is superior

element.className = 'newClass' completely wipes out all existing classes and replaces them with only 'newClass'.
In contrast, element.classList.add('newClass') safely preserves existing classes like btn btn-primary.

EVENT LISTENERS Critical Priority

addEventListener syntax, passing parameters, and onclick vs addEventListener.

Standard Preferred Syntax: targetElement.addEventListener(eventTypeString, callbackFunction);
Preferred Exam Patterns
const myBtn = document.getElementById('actionBtn');

// Pattern A: Arrow function (cleanest & fastest for exams)
myBtn.addEventListener('click', () => {
  console.log('Button clicked!');
});

// Pattern B: Named function
function handleClick(event) {
  event.target.textContent = 'Done!';
}
myBtn.addEventListener('click', handleClick); // Note: do NOT write handleClick()

onclick vs addEventListener: Preferred Exam Syntax

Criterion element.onclick = fn element.addEventListener('click', fn) (Preferred)
Multiple Handlers Overwrites previous handler. Only 1 function can run. Allows multiple independent listeners on the same element.
Separation of Concerns Often placed directly in HTML (onclick="fn()"), which is bad practice. Keeps HTML pure and puts logic 100% inside JavaScript file.
Exam Grader Expectation Might fail automated test regex if the question asks to "attach an event listener". 100% accepted and recommended across all testing platforms.

INPUT AND FORM VALUES Critical Priority

Reading input values, form submit handling, and e.preventDefault().

Reading from <input> and <textarea>
CRITICAL
Crucial Rule: Input fields DO NOT have .textContent or .innerHTML! Their user-entered text is stored in the .value property.
Form Submit & Input Value Handling
const loginForm = document.getElementById('loginForm');
const userInput = document.getElementById('username');
const displayMsg = document.getElementById('greeting');

loginForm.addEventListener('submit', (event) => {
  // 1. CRITICAL: Stop the browser from reloading the page
  event.preventDefault();

  // 2. Read typed value (trimmed of accidental spaces)
  const name = userInput.value.trim();

  // 3. Validate & Display
  if (name === '') {
    displayMsg.textContent = 'Please enter a username!';
    displayMsg.style.color = 'red';
  } else {
    displayMsg.textContent = `Welcome, ${name}!`;
    displayMsg.style.color = 'green';
    userInput.value = ''; // Clear input field after success
  }
});
🚨
The Page Reload Trap: If your button is inside a <form> or has type="submit", clicking it refreshes the whole page instantly, wiping out all your DOM changes! Always call event.preventDefault(); at the top of your submit listener.

ADDING AND REMOVING ELEMENTS High Priority

appendChild, append, and element.remove().

Operation Syntax Key Nuance
appendChild() parent.appendChild(node) Appends 1 node to end of parent. Returns the appended node.
append() parent.append(node1, "text", node2) Modern method; accepts multiple nodes and raw text strings.

DIGITAL CLOCK PATTERN Actual Reported Question

Complete memorizable implementation using new Date(), toLocaleTimeString(), and setInterval().

Multiple candidates in recent Accenture frontend coding rounds reported receiving an HTML skeleton with a <div id="clock">00:00:00</div> and were asked to make it tick every second with live system time.

HTML + CSS + JS Digital Clock (Memorize This!)
<!-- HTML -->
<div id="clockContainer">
  <h2 id="clock">00:00:00</h2>
</div>

<!-- CSS -->
<style>
  #clock { font-size: 32px; font-family: monospace; color: #7c3aed; }
</style>

<!-- JAVASCRIPT -->
<script>
  function updateClock() {
    const now = new Date();
    const timeString = now.toLocaleTimeString();
    document.getElementById('clock').textContent = timeString;
  }

  // 1. Call immediately so clock displays without a 1-second delay
  updateClock();

  // 2. Call every 1000 milliseconds (1 second)
  setInterval(updateClock, 1000);
</script>
⚡ Live Test Playground: Digital Clock
00:00:00
Ticking live using the exact code pattern above
💡
Why call updateClock() once before setInterval? setInterval(fn, 1000) waits a full 1000ms before executing the first tick. Calling updateClock() initially ensures the user doesn't see a frozen placeholder for the first second.

CHANGE IMAGE PATTERN High Priority

Swapping image src attribute upon button click.

Switching Image Source
<img id="bulbImg" src="bulb_off.png" alt="Bulb">
<button id="switchBtn">Turn ON</button>

<script>
  const bulb = document.getElementById('bulbImg');
  const btn = document.getElementById('switchBtn');

  btn.addEventListener('click', () => {
    if (bulb.src.includes('bulb_off.png')) {
      bulb.src = 'bulb_on.png';
      btn.textContent = 'Turn OFF';
    } else {
      bulb.src = 'bulb_off.png';
      btn.textContent = 'Turn ON';
    }
  });
</script>
💡
Browser Full URL Trap: bulb.src returns the full absolute URL (e.g. http://localhost:3000/bulb_off.png), so bulb.src === 'bulb_off.png' might evaluate to false! Always use bulb.src.includes('bulb_off.png') for reliable condition checking.

SIMPLE FORM VALIDATION PATTERN High Priority

Empty checking, error message injection, preventing reload.

Form Validation Script
const form = document.getElementById('contactForm');
const emailInput = document.getElementById('email');
const errorMsg = document.getElementById('errorBox');

form.addEventListener('submit', (e) => {
  e.preventDefault();
  const val = emailInput.value.trim();

  if (val === '') {
    errorMsg.textContent = 'Email cannot be empty!';
    errorMsg.style.color = '#ef4444';
    emailInput.style.borderColor = '#ef4444';
  } else if (!val.includes('@') || !val.includes('.')) {
    errorMsg.textContent = 'Please enter a valid email containing @ and .';
    errorMsg.style.color = '#ef4444';
  } else {
    errorMsg.textContent = 'Form submitted successfully!';
    errorMsg.style.color = '#10b981';
    emailInput.style.borderColor = '#10b981';
  }
});

COMMON EXAM TRAPS High Failure Causes

The 11 mistakes that cost candidates 100% of their score.

Trap Number Fatal Candidate Error How to Fix Instantly
Trap 1 Writing document.getelementbyid() with lowercase. JavaScript is strictly case-sensitive: must be document.getElementById().
Trap 2 Writing input.textContent instead of input.value. Input values live exclusively in .value!
Trap 3 Writing addEventListener('onclick', ...). Inside addEventListener, omit "on"! Use 'click', 'change', 'submit'.
Trap 4 Calling function during listener binding: btn.addEventListener('click', updateText()). Remove parentheses: btn.addEventListener('click', updateText). Writing () executes it immediately on load!
Trap 5 Writing classList.add('.active') with a dot. classList already knows it is a class! Write classList.add('active').
Trap 6 Writing CSS with hyphen: elem.style.background-color = 'blue'. Use camelCase in JS: elem.style.backgroundColor = 'blue'.
Trap 7 Omitting pixel units: elem.style.fontSize = 24. Must include units as string: elem.style.fontSize = '24px'.
Trap 8 Forgetting e.preventDefault() on form submit. The page reloads and immediately wipes out your changes. Call e.preventDefault().
Trap 9 Running script before HTML loads (returns null). Ensure script is placed right before </body> or wrap code inside document.addEventListener('DOMContentLoaded', () => { ... }).
Trap 10 Mismatched IDs between HTML and JS. Copy-paste ID strings directly from the HTML tab to prevent typos.
Trap 11 Rewriting or deleting existing HTML skeleton tags. Only write the JavaScript needed. The grader checks for the skeleton's original HTML structure.

1Typing #id inside getElementById.

3Forgetting e.preventDefault() on form submissions.
4Writing addEventListener('onclick', ...) with 'on'.
5Invoking function in listener: addEventListener('click', fn()).
6Typing a dot inside classList: classList.add('.box').
7Forgetting unit strings: elem.style.width = 100 (no 'px').
8Renaming existing skeleton HTML IDs or tags.
