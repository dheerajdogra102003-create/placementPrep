02 / Core Concepts

Cloud Computing Fundamentals

Know the concept in one sentence, then recognize it in a scenario.

01

Cloud Computing

Delivery of computing resources such as servers, storage, software and processing over the internet, usually on demand.

HIGH

Remember

  • Resources are accessed remotely.
  • On-demand provisioning is a key idea.
  • Pay-as-you-use is a common cloud model.
  • Reduces the need to own physical infrastructure.

Example

A startup rents computing resources from a cloud provider instead of buying servers.
Asked as: “Which technology provides computing resources over the internet on demand?”
Memory: Cloud = “use remote resources when you need them.”
02

Characteristics of Cloud Computing

Features that make cloud services flexible, shared and measurable.

HIGH

Remember

  • On-demand self-service — resources can be provisioned when needed.
  • Broad network access — access from connected devices.
  • Resource pooling — provider resources are shared.
  • Rapid elasticity — capacity can adjust quickly.
  • Measured service — usage can be monitored and billed.

Example

An online store increases resources during a sale and reduces them later.
Asked as: “Which characteristic enables pay-as-you-use measurement?” → Measured service.
03

Advantages & Disadvantages

Cloud can reduce infrastructure ownership while introducing dependency on provider services and connectivity.

HIGH

Advantages

  • Lower upfront hardware cost.
  • Easy accessibility.
  • Rapid scaling.
  • Provider-managed maintenance for many services.
  • Backup and recovery options.

Risks / Limits

  • Internet dependency.
  • Security and privacy concerns.
  • Less infrastructure control.
  • Possible provider outage.
  • Vendor dependency.
03 / Models

Deployment & Service Models

This is one of the highest-value areas for direct and scenario MCQs.

PUBLIC CLOUD

Public Cloud

Cloud infrastructure is offered by a provider and can serve multiple customers. Strong scalability and accessibility; less direct infrastructure control.

Scenario: A startup wants fast, scalable infrastructure without owning data-center hardware.
PRIVATE CLOUD

Private Cloud

Cloud infrastructure dedicated to a single organization. Useful where greater control, customization or isolation is required.

Scenario: An organization wants dedicated cloud infrastructure for sensitive workloads.
HYBRID CLOUD

Hybrid Cloud

Combination of private and public cloud environments, often used to balance control, security, flexibility and cost.

Scenario: Sensitive data stays private while scalable public resources handle other workloads.
04

Community Cloud

A cloud environment shared by organizations with common requirements, such as security, compliance or mission needs.

MEDIUM

Remember

  • Shared by a defined community.
  • Common goals or compliance needs are the clue.

Question pattern

Scenario: Several organizations with similar compliance requirements share a dedicated cloud environment. Which model? → Community Cloud.
05

IaaS — Infrastructure as a Service

Provides virtualized infrastructure such as compute, storage and networking; the customer manages more of the software stack.

HIGH

Remember

  • More control than PaaS/SaaS.
  • Provider handles physical infrastructure.
  • Customer typically manages OS, applications and data.
  • Common clue: “rent virtual servers/resources.”

Example + Trap

A company rents virtual machines and installs its own operating system and application.
Trap: IaaS is not the same as “complete application.”
Memory: IaaS = Infrastructure → “I manage more.”
06

PaaS — Platform as a Service

Provides a managed environment for developing and deploying applications without managing the underlying infrastructure.

HIGH

Remember

  • Developer focuses mainly on application code.
  • Provider manages infrastructure and platform components.
  • Faster development and deployment.
  • Less infrastructure customization than IaaS.

Example + Trap

A developer deploys an application without managing the server OS.
Trap: “Developer does not manage underlying infrastructure” strongly points to PaaS.
Memory: PaaS = Platform → “I bring the code.”
07

SaaS — Software as a Service

Ready-to-use software delivered over the internet; the provider manages the underlying infrastructure and application.

HIGH

Remember

  • End user mainly uses the application.
  • Little or no local installation.
  • Provider handles updates and infrastructure.
  • Typical clue: “access software through browser.”

Examples

Gmail, Google Docs and similar browser-based applications.
Asked as: “Which model gives the user a ready-to-use application?” → SaaS.
Memory: IaaS → Build infrastructure | PaaS → Develop | SaaS → Use.
08

Shared Responsibility Model

Cloud security responsibilities are divided between the provider and the customer; the exact split depends on the service model.

HIGH

Remember

  • Provider is responsible for the cloud infrastructure it operates.
  • Customer remains responsible for what it controls.
  • IaaS generally leaves more security/configuration responsibility with the customer.
  • SaaS shifts more operational responsibility to the provider.

Question pattern

Scenario: A company leaves its cloud storage publicly accessible because of a bad setting. Who failed to configure the resource correctly? → Customer-side responsibility.
04 / Infrastructure

Virtualization

Understand the physical → hypervisor → VM relationship.

09

Virtualization

Technology that creates logical/virtual resources from physical computing resources, allowing multiple isolated environments to share hardware.

HIGH

Remember

  • Improves resource utilization.
  • Reduces dependence on separate physical machines.
  • Supports isolation between virtual environments.
  • Virtualization is a foundation of many cloud environments.

Example

One physical server runs several independent virtual machines.
Asked as: “Which technology allows multiple VMs to run on one physical host?” → Virtualization.
10

Hypervisor

Software layer that creates and manages virtual machines and allocates physical resources to them.

HIGH

Remember

  • Manages VMs.
  • Allocates CPU, memory and other resources.
  • Provides isolation between virtual machines.

Question pattern

Which component creates and controls VMs? → Hypervisor.
11

Types of Virtualization

Virtualization can be applied to different resources such as servers, networks, storage, desktops and applications.

MEDIUM

Know the clue

  • Server: one physical server → multiple virtual servers.
  • Network: logical network segments over physical networking.
  • Storage: multiple physical storage resources → virtual pool.
  • Desktop: desktop environment hosted centrally.
  • Application: application runs in an isolated/virtual environment.

MCQ trick

Look at the noun after “virtualization.” That usually tells you what resource is being abstracted.
05 / Performance

Scaling, Elasticity & Reliability

Scenario questions often hide the answer inside words such as “sudden spike,” “growth,” “failure” and “availability.”

SCALABILITY

Scalability

Ability of a system to handle increasing workload by adding or increasing resources.

Clue: business grows and infrastructure must support more users.
ELASTICITY

Elasticity

Ability to automatically or rapidly increase and decrease resources as workload changes.

Clue: sudden traffic spike during a sale, followed by a drop later.
AUTO-SCALING

Auto Scaling

Automatically adjusts resource capacity according to demand or configured rules.

Clue: “increase instances automatically when CPU/traffic rises.”
HIGH AVAILABILITY

High Availability

Designing systems to remain available with minimal downtime, often using redundancy.

Clue: “keep the application running even if one component fails.”
FAULT TOLERANCE

Fault Tolerance

Ability of a system to continue operating despite a component failure.

Clue: failure occurs, but service continues without interruption.
LOAD BALANCING

Load Balancing

Distributes incoming traffic across multiple servers/resources to avoid overloading one.

Clue: many servers share incoming requests.
06 / Data

Cloud Storage

The most important distinction is what kind of data access the application needs.

12

Cloud Storage

Cloud storage provides remote storage capacity accessible over a network, allowing data to be stored without relying solely on local physical devices.

HIGH

Remember

  • Accessible remotely.
  • Can scale with demand.
  • Used for files, media, application data, backups and databases.

Question pattern

Asked as: “Which storage type is best for massive collections of images and videos?” → Object storage.

07 / Security

Cloud Security & IAM

Security questions are usually recognition questions: identify the threat, control or access concept.

IAM

Identity & Access Management

Controls which identities can access which cloud resources and what actions they can perform.

MFA

Multi-Factor Authentication

Requires more than one authentication factor, such as password + OTP.

ENCRYPTION

Encryption

Transforms readable data into a protected form so unauthorized parties cannot easily understand it.

13

IAM Components

IAM manages identities, permissions and access rules for cloud resources.

HIGH

Remember

  • User: individual identity.
  • Group: collection of users managed together.
  • Role: set of permissions associated with a job/use case.
  • Policy: rules defining allowed or denied actions.

Example

Students can view content, teachers can upload marks and admins can manage the entire system.
Scenario: “Give developers read-only access to storage.” → IAM policy/permission configuration.
14

Authentication vs Authorization

Authentication verifies who you are. Authorization determines what you are allowed to do.

HIGH

Remember

  • Password/OTP → authentication.
  • Permission to read/write/delete → authorization.
  • Authentication normally comes before authorization.

Trap

“Who are you?” → Authentication.
“What can you access?” → Authorization.
Memory: AuthN = Name/identity | AuthZ = Zone/permissions.
THREAT

Data Breach

Sensitive information is accessed or exposed to unauthorized parties.

THREAT

Data Loss

Data is deleted, corrupted or becomes permanently unavailable.

THREAT

Misconfiguration

Incorrect settings expose resources, such as accidentally public storage.

THREAT

Insecure API

A weakness in a cloud service interface can expose functionality or data.

THREAT

Insider Threat

A trusted internal user misuses legitimate access.

THREAT

Account Hijacking

An attacker gains unauthorized access by compromising credentials or identity.

15

Backup & Disaster Recovery

Backup keeps recoverable copies of data. Disaster recovery focuses on restoring systems/services after a disruptive event.

HIGH

Remember

  • Backup = recover the data.
  • Disaster recovery = restore the service/environment.
  • Both support business continuity.

Scenario

“Database is accidentally deleted and a copy is restored.” → Backup/recovery.
“Primary environment fails and service is restored elsewhere.” → Disaster recovery.
08 / Expand Your Score

Medium-Priority Topics

Know the one-line definition and the scenario clue. Do not spend excessive time on implementation details.

SERVERLESS

Serverless Computing

Run application functions without managing servers directly. The provider handles infrastructure and scaling.

Clue: “No server management + event-driven function.”
CONTAINERS

Containers vs VMs

Containers share the host OS kernel and package applications with dependencies; VMs virtualize a complete machine environment.

Clue: Containers are generally lighter than full VMs.
CDN

CDN

Content Delivery Network caches/distributes content closer to users to reduce latency.

Clue: “Users in different locations need faster static content.”
NETWORKING

VPC & Subnet

VPC is a logically isolated cloud network. A subnet is a smaller network segment inside it.

Clue: “Private logical network in cloud.”
DNS

Cloud DNS

Maps domain names to network destinations such as IP addresses or other endpoints.

Clue: “Translate website name to network destination.”
VPN

VPN

Creates a protected connection over a public network, often used to connect users or networks securely.

Clue: “Secure private connection over the internet.”
REGION / AZ

Region vs Availability Zone

A region is a geographic cloud location; availability zones are isolated locations within a region designed for resilience.

MULTI-TENANCY

Multi-Tenancy

Multiple customers share underlying provider infrastructure while remaining logically isolated.

CAPEX / OPEX

CapEx vs OpEx

CapEx is upfront capital investment; OpEx is ongoing operational spending. Cloud consumption commonly aligns with OpEx.

MONITORING

Cloud Monitoring

Tracks performance, availability and activity to identify issues and unusual behavior.

MIGRATION

Basic Cloud Migration

Moving applications/data from on-premises infrastructure to cloud environments.

DIFFERENTIATOR

Vendor Lock-in / Multi-Cloud

Vendor lock-in makes switching providers difficult. Multi-cloud uses services from more than one cloud provider.

10 / Avoid Easy Mistakes

Common MCQ Traps

Scalability ≠ ElasticityScalability focuses on handling growth; elasticity emphasizes rapid adjustment with changing demand.
Authentication ≠ AuthorizationAuthentication verifies identity; authorization checks permissions.
IaaS ≠ PaaSIaaS gives more infrastructure control. PaaS removes more infrastructure management from the developer.
Public Cloud ≠ “No Security”Public cloud can have strong security controls; the key distinction is shared/provider-operated infrastructure and responsibility.
IAM ≠ Authentication onlyIAM is broader: identities, permissions and access policies.
Object ≠ Block ≠ FileChoose based on access pattern and workload, not simply on “storage.”
Backup ≠ Disaster RecoveryBackup preserves recoverable data; disaster recovery restores services/environments after disruption.
Hypervisor ≠ VMHypervisor manages VMs; a VM is the virtual machine environment itself.
11 / Question Recognition

How Questions Are Asked

Do not only memorize definitions. Learn the wording that points to the concept.

DIRECT

Definition MCQ

“Which model provides virtualized computing resources over the internet?”

→ IaaS
DIFFERENCE

Comparison MCQ

“Which model allows developers to deploy without managing the underlying OS?”

→ PaaS
EXAMPLE

Example Recognition

“A browser-based ready-to-use email application is an example of which model?”

→ SaaS
APPLICATION

Most Suitable

“A sale causes traffic to increase suddenly and later return to normal. Which feature is most relevant?”

→ Elasticity / Auto Scaling
STATEMENT

Statement-Based

“Identify the correct statement about IAM, virtualization or shared responsibility.”

→ Look for the precise responsibility/access distinction.
NOT / EXCEPT

Negative MCQ

“Which of the following is NOT a characteristic of cloud computing?”

→ Eliminate on-demand access, resource pooling, elasticity and measured service first.
12 / Scenario Training

Scenario-Based Question Patterns

These are representative patterns, not claimed as official company previous-year questions.

Scenario 01 · E-commerce

Traffic suddenly increases during a sale.

The company wants resources to increase automatically and reduce after the sale.

Answer: Elasticity + Auto Scaling
Scenario 02 · Developer

Developer wants to deploy code without managing the OS.

The provider should manage the infrastructure and platform environment.

Answer: PaaS
Scenario 03 · Sensitive Data

A bank wants dedicated infrastructure for sensitive workloads.

The organization prioritizes control and isolation.

Answer: Private Cloud
Scenario 04 · Mixed Workloads

A company keeps sensitive workloads private but uses public cloud for scalable workloads.

It needs a combination of deployment approaches.

Answer: Hybrid Cloud
Scenario 05 · Storage

An application stores millions of images and videos.

The data is large-scale and unstructured.

Answer: Object Storage
Scenario 06 · Database

A database needs high-performance disk-like storage.

The workload needs fast block-level access.

Answer: Block Storage
Scenario 07 · Access

Employees should receive different permissions based on their job roles.

The company needs centralized identity and permission management.

Answer: IAM / Role-based permissions
Scenario 08 · Login

Users must enter a password and then an OTP.

Two different authentication factors are required.

Answer: MFA
Scenario 09 · Security Incident

A storage resource was accidentally made public.

The exposure happened because of an incorrect configuration.

Answer: Security misconfiguration
Scenario 10 · Failure

A server fails but the application continues operating.

The system was designed with redundancy so a component failure does not stop the service.

Answer: Fault tolerance / High availability
